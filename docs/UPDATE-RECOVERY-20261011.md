# v0.1.2: 開いたままの旧版とサービス再確認の案内

2026-10-11。公開サイトの更新後も古いタブが128-token固定版を実行していたため、回答が短く途切れる問題が継続していました。

## 確認した原因

- 利用者のタブが読み込んでいたentryは `index-Ap8jxKnX.js`。設定画面には `Response length (tokens) 128` と `Limited to 128 tokens during this preview.` が表示されていました。
- 同時点の公開HTMLは `index-DMbYlZeA.js` を参照しており、v0.1.1の4,096-token対応コードは配信済みでした。公開側の更新だけでは実行中のJavaScriptは置き換わりません。
- `Payment not yet verified` は支払いの精算状態であり、この128-token固定とは別です。過去の回答を自動で補完したり、推論を再送したりはしません。

## 変更

- 同じorigin・同じ配信パスのHTMLを読み、entryの変更を見つけたら `Reload app` を表示します。起動時、タブへの復帰時、表示中の5分間隔で確認します。開発用のVite scriptや失敗応答は更新扱いにしません。
- 自動リロードはしません。送信・支払い・ウォレット操作が進行中の場合と下書きがある場合はボタンを無効にします。既存のprofile、SDK、保存領域、入金情報は変更しません。
- サービス確認が失敗した画面には `Chat temporarily paused`、失敗した確認項目、`Retry service check` を表示します。確認成功まで新規操作は止め、同じ入金で再確認できます。出金・再入金は再確認の条件ではありません。
- サービス再確認は読み取りのみです。再失敗した場合も再確認ボタンを残し、成功した場合は状態を更新します。
- 保存済みの回答長設定は保持します。必要なら `Appearance and chat` の `Response length` を4,096に変更します。旧SDKの復旧版の128-token制約は維持します。

今回のタブには更新通知そのものがまだ存在しないため、一度明示的に最新版へ再読み込みする必要があります。
