# 新規支払いの自動復旧（2026-10-24）

## 反映した方針

利用者から「運営負担で自動精算する」と明示的に承認された方針を、公開サイトが
利用するzkapiバックエンドへ反映した。対象は **2026-10-24T16:28:02+09:00 以降に作成される
支払いセッション**。既存ウォレットで作る新しい支払いも対象となる。
アカウントの登録日による判定ではない。既存sessionへ遡って適用しない。

既存SDK `.16` 復旧プレビューのレシート形式で利用できるため、この更新に伴う
フロントエンド・SDK・WASMの再配信は行っていない。GitHubの新しいリリース公開でもない。

## 再発防止

以前の処理は、ローカルの保存準備より前に送信権限を記録していた。
このため、保存領域の権限不備など実際のprovider送信より前の失敗まで
「発行結果不明」になり得た。新しい処理では、workerが入力・資格情報・保存領域を
確認して永続claimを作った後に、controlが送信権限を記録してGOを渡す。
workerは再度期限・DBの状態を確認してから一度だけ送信する。

準備中に失敗し、workerの終了を確認できた場合は、既存の署名付き
`not_dispatched` / `NOT_DISPATCHED` レシートで請求0として自動精算する。
ledgerと独立signerの両方が未送信・停止の根拠を検査する。

通信断等で送信後の発行結果が不明な場合は、通常のキー照合を先に試す。
新方針の対象で、未有効化・キー参照なし・利用記録なし・全試行の停止確認済みであれば、
元の発行期限と300秒以上の猶予期間の経過後に運営負担で自動精算する。
通常の60秒期限なら開始から約6分が時間条件の目安で、照合や停止確認で延びる場合がある。

レシートは `waived_unknown` / `UNKNOWN_OPERATOR_LOSS`、利用者請求0。
provider使用量・費用・運営損失額は `null` を維持し、不明な費用をゼロと見なさない。
元のAUTH予約と独立signerによる後継状態の検証は保持する。
自動メッセージ再送、キー再発行、入出金は行わない。

対象sessionが猶予期間を待つ間は、手動対応が必要であるという表示を抑える。
このstatus判定は読み取り専用で、GETによって金融記録やprovider呼出しは増えない。

## 残る条件

実行中workerの停止未確認、DB障害、不正な署名証拠は自動精算の対象にしない。
キー参照が保存されている通常利用の終了処理も、既存の使用量照合による復旧を使う。
したがって、あらゆる障害で支払い待ちが発生しなくなったという保証ではない。

当初のincidentでは、claim保存先とsystemdの書き込み許可先の不一致を確認し修正した。
元の例外が保存されていないため、その不一致が元の一件の直接原因だったと断定はできない。
この更新は、同種の準備失敗を確実に未送信として扱い、送信後の不明状態にも
承認済みの費用負担方針に基づく復旧経路を設けたもの。

## 配備と検証

- 同じソースmanifestからLinux版control・dispatcher・signerをビルドし、3実行ファイルを照合。
- 公開受付を止め、処理中の仕事がないことを確認してDB・claim・signer journalをバックアップ。
- 既存金融記録・claim・署名履歴・鍵・profileを保持し、新方針を登録してから受付を再開。
- 公開サイト、readiness、従来profileはHTTP 200。control・signer・indexerはavailable。
- 準備失敗、GO拒否、不明結果、期限・停止・cutoff条件、二重処理防止をローカルで検証。
- 実worker、PostgreSQL、実証明、独立signerを含む復旧テストとClippy・整形・契約検査が成功。
- status表示の4ケースを検証し、GET前後の金融記録・provider呼出し件数の不変を確認。

ローカルの障害テストはRPC/providerの応答を模擬している。稼働中のproviderへ
障害注入はしておらず、providerの最終請求額を独立に確認した結果ではない。
公開チャットで新しい検証メッセージを一度送信し、`openai/gpt-4o-mini` から
`動作確認できました。` という応答を受け取った。`Settle charges` 後のsessionは
`SETTLED`、通常の `metered` / `OPENROUTER_USAGE` レシート、署名済み精算あり。
発行試行は1件、未停止試行は0件。請求は8100 nano USDC（0.0000081 USDC）、
画面の丸め表示は `Settled · 0.000009 USDC` だった。

再読み込みして同じウォレットへ接続し、保存済みdepositの表示残高1.999096 USDC、
`Ready to chat.`、未解決支払いなし、応答と精算表示の保存を確認した。
サーバー側でも既存4session、36claim、元の署名履歴を保持し、6サービスがactive、
signer再照合成功・署名拒否0件を確認した。
[配備・検証結果](evidence/automatic-payment-recovery-20261024.json)に要約を保存した。
